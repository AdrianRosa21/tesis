# Análisis de Seguridad y Riesgos Técnicos

El siguiente análisis de seguridad se basa en la inspección del código fuente y las variables de configuración expuestas en el repositorio. Al tratarse de una aplicación sin backend, muchos de los vectores tradicionales (Inyección SQL, CSRF) no aplican, pero emergen vulnerabilidades críticas de otra índole.

## Inventario de Hallazgos

| Hallazgo | Severidad | Evidencia | Impacto | Escenario posible | Recomendación |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Exposición de API Key de terceros en el código cliente. | **Crítico** | En `.env` (`VITE_GEMINI_API_KEY`) y en `PdfReaderPage.tsx:160` se llama directamente al SDK en el navegador. | Un atacante puede extraer la llave desde el código fuente minificado (o interceptando red) y agotar las cuotas o dinero de la cuenta de Google Cloud asociada. | Cualquier usuario que visite la web inspecciona la pestaña "Network" y obtiene la clave para uso propio. | Mover la llamada al SDK de Gemini a un backend intermediario seguro o función *Serverless* (AWS Lambda, Vercel Edge). |
| Posible fuga de información sensible enviada a modelo de IA. | **Alto** | `PdfReaderPage.tsx:166`. El contenido de todo el Canvas del PDF se envía a Google Gemini sin anonimización. | Infracción a normativas de protección de datos (GDPR/HIPAA). Documentos confidenciales cargados localmente abandonan el equipo y son enviados a servidores de terceros. | El usuario carga un registro médico personal en PDF para escucharlo; el documento privado es enviado a servidores de Google. | Informar explícitamente en la `HomePage` que las descripciones de IA enviarán datos a la nube. Permitir el uso del sistema con la IA apagada. |
| Archivo `.env` expuesto en repositorio. | **Crítico** | El comando `list_dir` encontró un `.env` junto a un `.gitignore`. Es posible que el `.env` (conteniendo el `API_KEY` funcional) esté subido en control de versiones local o remoto. | Clave filtrada universalmente. | Bots de GitHub detectan la clave en minutos. | Eliminar la clave actual, revocarla en la consola de Google, asegurar que `.env` esté en `.gitignore`. |
| Ausencia de control de sanitización de salidas auditivas (Audio Injection). | **Medio** | `App.tsx` lee en voz alta `input.value` (L60) sin escapar caracteres extraños. | Bajo en gravedad (no ejecuta JS), pero un usuario malintencionado que comparte un archivo PDF podría insertar texto para crashear el motor SpeechSynthesis. | Un PDF malicioso inyecta Unicode corrupto, colgando el lector de pantalla. | Limpiar cadenas con expresiones regulares antes de inyectarlas en `SpeechSynthesisUtterance`. |
| Vulnerabilidades por dependencias del cliente (XSS en pdf.js). | **Bajo** | Librería `pdfjs-dist` y dependencias gestionadas por `npm` sujetas a vulnerabilidades conocidas. | Posibilidad de comprometer el navegador del cliente si procesan un PDF manipulado expresamente. | El usuario descarga un PDF troyanizado, el cual ejecuta scripts al ser parseado. | Mantener dependencias actualizadas; correr `npm audit` frecuentemente. |

## Resumen y Posición Actual
La postura de seguridad del proyecto es deficiente para un entorno en producción. La decisión arquitectónica de consumir directamente un servicio pagado de terceros (Google Gemini API) desde un cliente de navegador (SPA) rompe el principio fundamental de no exponer secretos. Este diseño es aceptable exclusivamente en un entorno controlado (demostración de tesis o prueba de concepto), pero no es apto para despliegue público sin antes crear un túnel backend.
